# مصفوفة التوافق والأنظمة المدعومة (Support Matrix) 📋

توفر هذه الوثيقة دليلاً مرجعياً كاملاً للأنظمة المعمارية والمنصات ومحركات التشغيل التي يدعمها **LocalPilot**.

---

## 🖥️ المنصات والأنظمة المدعومة

| نظام التشغيل | المعماريات المدعومة | تسريع العتاد (Hardware Acceleration) | حالة الدعم |
| :--- | :--- | :--- | :--- |
| **macOS** (12.0+) | Apple Silicon (M1/M2/M3/M4) | **Metal GPU** والذاكرة الموحدة (Unified Memory) | ✅ مدعوم بالكامل (أفضل أداء وسرعة) |
| **macOS** (12.0+) | Intel x86_64 | AVX2 / CPU فقط | ⚠️ مدعوم (وضع المعالج فقط) |
| **Linux** | x86_64 (Ubuntu, Fedora, Arch, Debian) | **NVIDIA CUDA** أو AVX2/AVX512 (CPU) | ✅ مدعوم بالكامل |
| **Linux** | aarch64 (ARM64) | ARM NEON / CPU | ✅ مدعوم |

## 🧭 مصفوفة المحاور الثلاثة للتشغيل (3-Axis Matrix)

يقوم LocalPilot بفصل عملية التنفيذ إلى ثلاثة محاور مستقلة:

```text
                  ┌────────────────────────┐
                  │ 1. محرك الاستدلال      │
                  │    (Inference Backend) │
                  └───────────┬────────────┘
                              │
          ┌───────────────────┴───────────────────┐
          ▼                                       ▼
┌───────────────────────┐               ┌───────────────────────┐
│ 2. خدمة الإدارة        │               │ 3. أسلوب التنفيذ      │
│    (Execution Service)│               │    (Deployment Method)│
└───────────────────────┘               └───────────────────────┘
```

### 1. محركات الاستدلال (Inference Backends):
- **llama.cpp**: المحرك الافتراضي فائق السرعة، يدعم صيغ GGUF المكممة، ويوفر تحكماً دقيقاً في تقسيم الطبقات بين كارت الشاشة والمعالج.
- **vLLM**: موجه للأنظمة المتقدمة ومخدمات Linux المزودة ببطاقات NVIDIA الاحترافية ذات الذاكرة الكبيرة.

### 2. خدمات الإدارة (Execution Services):
- **مضمن / محلي مباشر (Direct Native)**: تشغيل مباشر لأوزان GGUF دون الحاجة لأي خدمات وسيطة.
- **Ollama**: تكامل هادئ مع خدمة Ollama المثبتة لديك لاستدعاء وإدارة النماذج عبر مكتبتها.
- **LM Studio / llmster**: اكتشاف واستخدام الخدمات القائمة بدون تكرار التشغيل.
- **Docker Model Runner**: تشغيل الحاويات المعزولة عند الرغبة.

### 3. أساليب التنفيذ (Deployment Methods):
- **عملية عامل مباشرة (`direct_worker`)**: تشغيل نموذجك في عملية فرعية معزولة تملك منفذاً خاصاً وتفريغاً فورياً للذاكرة عند الإغلاق.
- **خدمة واجهة محلية (`local_api_service`)**: الاتصال بواجهة برمجية محلية متوافقة مع معايير OpenAI أو خادم Ollama المحلي.
- **حاوية (`container`)**: عزل كامل داخل بيئة Docker.

## 🛡️ ضمانات أمان العمليات والملفات

1. **حماية العمليات الخارجية:** إذا تم اكتشاف Ollama أو LM Studio قيد التشغيل بالفعل، فلن يقوم LocalPilot بقتل العملية أو إغلاقها قسراً.
2. **تفريغ هادئ للذاكرة:** يتم إرسال طلب تفريغ النموذج (`keep_alive=0` أو `/models/unload`) عند التوقف، مما يتيح لخادم الخلفية البقاء حياً لخدمة أدواتك الأخرى.
3. **حماية التخزين المشترك:** لا يقوم LocalPilot بحذف أي ملفات أوزان مشتركة إلا إذا كانت مسجلة بالكامل تحت إدارته ولم تعد مرتبطة بأي تثبيت نشط.
